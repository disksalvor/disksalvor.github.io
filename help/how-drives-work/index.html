A drive is a stack of layers

Every drive, whatever its type, works the same way from the computer's side: it's one long row of numbered blocks. Everything else (partitions, file systems, folders, file names) is just data written into those blocks by convention, and each layer only makes sense if the layer under it can be read.

When Windows says "you need to format the disk", usually only the file-system layer is damaged. The layers below (the disk and its sectors) still work, and so do most of the files' contents. That's why recovery tools read the raw sectors themselves instead of asking Windows for files.

How a drive connects, and why it matters

SATA and NVMe drives talk to Windows directly. A USB drive talks through a bridge chip that converts USB commands into the drive's own language. Bridges are why the same disk can behave differently in different enclosures: some hide the health log, some time out and reset the connection when the disk struggles, and some encrypt everything (see Encryption).

LinkNotes for recovery
SATA (inside a PC, or a SATA dock)Most direct and predictable. The best way to connect a failing hard disk, if you can get it out of its case (unless its bridge encrypts it).
NVMe / PCIeVery fast; health log always available.
USB, BOT modeOlder, simpler protocol. Slower, but tolerant of slow drives.
USB, UAS modeFaster, queues commands, can pass TRIM. Some bridges reset the whole connection when a failing drive stalls.
Card readerThe reader has its own controller. An empty slot still shows a drive letter with no size. Readers rarely pass TRIM.
Hubs, docks, front-panel portsAdd another chip and weaker power. Plug a fragile drive straight into the computer.

Platters and flash

On a hard disk, consecutive sectors sit next to each other on a track, and deleted data stays put until something is written over it. On flash, the controller's map (the flash translation layer) puts data anywhere, moves it around to spread wear, and may erase freed space by itself.

So on hard disks physical position matters: the heads travel to each spot, and reading in disk order is faster and gentler than jumping around (DiskSalvor's "disk order" and "one sweep" copy modes use this). On flash, order barely matters.

Both kinds keep spare blocks. When a spot goes bad, the drive quietly maps that sector number to a spare. The drive's health log counts these swaps ("reallocated sectors"), and the ones it couldn't read yet ("pending sectors").

Sectors and clusters

TermMeaning
SectorThe smallest unit a drive reads or writes: 512 bytes, or 4,096 bytes on newer drives.

OffsetA position in bytes from the start of the disk: LBA × sector size.

MBR and GPT partition tables

A disk can also have no partition table: the file system simply starts at sector 0. That's common on USB sticks and memory cards ("superfloppy"). It's normal, not damage.

A typical Windows system disk (GPT): an EFI system partition (100–260 MB, FAT32, the boot loader), a 16 MB Microsoft Reserved partition (empty, no file system), the Windows partition (NTFS, C:), and a Recovery partition (about 0.5–1 GB). External drives usually have one big partition.

Inside NTFS

The boot sector says where the MFT starts. The MFT holds one record per file or folder, and each record says where that file's contents are in the data area, possibly in several pieces (fragments). Each folder also keeps a sorted list of its contents in INDX blocks, so names are written in two places.

A record stores its folder only as a number. To show "Photos\2024\beach.jpg", the folder's own record must be readable too. If it isn't, the file is fine but has lost its place. That's why DiskSalvor can show "Lost folder #N" and then try to restore the real folder names from the INDX blocks (deep search).

Other system files: $LogFile (a journal of changes in progress, replayed at mount), $Bitmap (which clusters are in use), $UpCase, $Secure (permissions), $Extend\$UsnJrnl (a log of recent changes), and the MFT's own bitmap.

Inside FAT32 and exFAT

Folders are just files containing a list of 32-byte entries (name, size, dates, first cluster). Long names are stored in extra entries in front of the short one.

Deleting on FAT32 replaces the name's first letter and sets its chain to 0. The start cluster survives, so unfragmented files come back whole; fragmented ones only partly. exFAT keeps a "stored in one piece" flag per file and a bitmap of used clusters, so deleted files there are often fully recoverable.

Backups: FAT32's boot sector is copied at sector 6 and the FAT is usually stored twice. exFAT's boot region (sectors 0–11) has a checksum and a full copy at sectors 12–23, but usually only one FAT.

When the file index is damaged

This is the most common reason a drive suddenly shows as RAW after a power cut, a forced reboot or an unplug during copying: the writes that were in flight were to the index, so the index is what's half-written. The file contents are usually untouched. Recovery means reading the surviving index records directly (and, for the missing ones, finding files by their content type).

Bad sectors, retries and hangs

Every sector carries an error-correcting code. When the data doesn't match it, the drive retries, then reports a read error.

DiskSalvor reads gently: on an error it skips the block and comes back later in small steps, one physical sector (usually 4 KB) at a time; when the drive stops responding it moves on instead of waiting; it keeps a map of every problem; and it warns you when errors repeat.

The health log (S.M.A.R.T.)

Drives keep their own statistics. DiskSalvor reads them directly (the same way CrystalDiskInfo does): NVMe SSDs always, SATA drives directly, and USB drives when the bridge allows it. Memory cards and most sticks have no health log.

Each item has a count (the real number of events) and a score (the drive's own 1–253 rating; lower is worse). The drive only calls itself "failing" when a score drops to its fail line, which is often too late. The counts are more useful:

Self-tests: the drive can test itself (short ≈ 2 min, extended = the whole surface). Its log of past results is shown too. An extended test on a failing drive takes hours and adds wear, so copy your data first.

Encryption

BitLocker is unlocked by Windows with your password or the 48-digit recovery key; once unlocked the disk works in any PC. Many WD My Passport / My Book drives encrypt everything in their USB bridge, even with no password set: take the disk out of its case and it reads as noise, so it only works through its own (or an identical) bridge.

How DiskSalvor reads a drive

DiskSalvor opens the disk as raw sectors (\\.\PhysicalDriveN) and reads the layers itself: partition table, then each file system, then the files. It never writes to the drive it's examining, works even when Windows calls the volume RAW, and reads gently with a full record of every problem. Its guided steps follow the safe order: look → check health → copy (whole drive or your files) → find what's missing → repair last.
